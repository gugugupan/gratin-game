## 1. 产品概述

### 1.1 产品定位

单人逻辑推理益智游戏。玩家根据一组规则与条件，对地图进行**区域划分**，推导出**唯一正确**的规划方案。

核心体验类比数独 / Nonogram / Murdoku / 爱因斯坦逻辑谜题，但推理对象从「数字 / 人物」变为「**空间区域**」。

### 1.2 核心卖点

| 卖点 | 说明 |
| --- | --- |
| 极低学习成本 | 只需理解「地图、区域、条件」三件事即可上手 |
| 高推理深度 | 简单规则可组合出大量逻辑链 |
| 天然每日挑战 | 单关 3~10 分钟、唯一解、可分享 |
| 主题可无限扩展 | 底层规则不变，皮肤可换（土地规划、王国分封、企业购地、太空殖民、魔法领地等） |

### 1.3 目标用户

- 喜欢数独 / Nonogram / 逻辑谜题的休闲玩家
- 通勤碎片时间玩家（单局短）
- 益智游戏内容创作者 / 社交分享型用户

## 2. 核心概念与术语

| 术语 | 定义 |
| --- | --- |
| 地图 Board | N×M 的网格，是关卡的物理空间 |
| 格子 Cell | 地图的最小单位，可携带 0~多个属性（地形/资源） |
| 属性 Attribute | 格子的标签，分「地形」与「资源」两类，可叠加（如 森林+金矿） |
| 区域 Region | 由若干连通格子构成的集合，归属于某个「组织」 |
| 组织 Org | 区域的所有者（如 矿业公司、农业公司），一关可有多个 |
| 条件 Constraint | 关卡规则，约束区域的面积/包含/邻接/边界/相对关系等 |
| 解 Solution | 一种把每个格子分配给某区域（或留空）的完整方案 |
| 唯一解 | 满足全部条件的方案有且仅有一个 |
| 笔记标记 Mark | 玩家辅助推理用的临时标记（可能/排除/确认） |

---

## 3. 核心游戏循环

```
阅读条件 → 观察地图 → 推理区域范围 → 标记排除
   → 确定区域边界 → 验证全部条件 → 完成关卡
```

设计目标：每一步推进都依赖**逻辑推导**，而非试错或猜测。

## 4. 核心系统

### 4.1 地图系统

- 形状：N×M 矩形网格。
- 推荐尺寸：5×5（入门）~ 10×10（高级）。
- 格子属性分两类，可组合：
  - **地形（terrain）**：森林、湖泊、山脉、农田、沙漠、道路、城市、平原。
  - **资源（resource）**：金矿、铁矿、煤矿等。
- 部分地形可作为「不可分配/障碍」（如湖泊、山脉，视关卡设定），即不能归属于任何区域。

> 形式化：每个 Cell 拥有 `terrain: TerrainType` 与 `resources: Set<ResourceType>`，以及可选 `blocked: bool`（障碍，不可被划入区域）。

### 4.2 区域系统

区域的硬性规则：

1. **唯一归属**：每个可分配格子至多属于一个区域。
2. **连通性**：区域内格子必须 4-邻接连通（默认；可配置为 8-邻接）。
3. **形状约束**：支持任意形状 / 矩形 / 正方形 / L 形 / 自定义形状。
   - **MVP 阶段仅支持矩形**，降低交互与求解复杂度。
4. **覆盖要求**（关卡可配置）：
   - `FULL_COVER`：所有非障碍格子都必须被某区域覆盖。
   - `PARTIAL_COVER`：允许存在「未分配」空地。

### 4.3 条件系统（关卡核心）

条件是关卡的灵魂。下表给出**形式化定义**，供求解器与生成器统一使用。

每条条件统一结构：`{ type, target, params }`，其中 `target` 指向某区域/组织（或全局）。

#### 4.3.1 面积条件 Area

| 子类型 | 含义 | 参数 |
| --- | --- | --- |
| `AREA_EQ` | 面积 = K | `{ value: K }` |
| `AREA_GE` / `AREA_LE` | 面积 ≥ / ≤ K | `{ value: K }` |
| `AREA_MAX` / `AREA_MIN` | 在所有区域中面积最大/最小 | — |

#### 4.3.2 包含 / 排除条件 Contain / Exclude

| 子类型 | 含义 | 参数 |
| --- | --- | --- |
| `MUST_CONTAIN` | 必须包含某属性 | `{ attr }` |
| `MUST_NOT_CONTAIN` | 不能包含某属性 | `{ attr }` |
| `CONTAIN_COUNT_EQ/GE/LE` | 包含某属性的格子数 =/≥/≤ K | `{ attr, value }` |

#### 4.3.3 邻接条件 Adjacency

| 子类型 | 含义 | 参数 |
| --- | --- | --- |
| `MUST_TOUCH_TERRAIN` | 区域必须接触某地形 | `{ terrain }` |
| `MUST_NOT_TOUCH_TERRAIN` | 区域不能接触某地形 | `{ terrain }` |
| `MUST_TOUCH_REGION` | 必须与某区域相邻 | `{ region }` |
| `MUST_NOT_TOUCH_REGION` | 不能与某区域相邻 | `{ region }` |

> 「接触/相邻」定义：区域内某格与目标格/区域 4-邻接。

#### 4.3.4 边界条件 Border

| 子类型 | 含义 |
| --- | --- |
| `MUST_ON_EDGE` | 区域必须触及地图边缘 |
| `MUST_NOT_ON_CORNER` | 区域不能占据地图角落 |

#### 4.3.5 相对条件 Relative

| 子类型 | 含义 | 参数 |
| --- | --- | --- |
| `AREA_LARGER_THAN` | A 面积 > B | `{ a, b }` |
| `AREA_EQUAL_TO` | A 面积 = B | `{ a, b }` |
| `DIRECTION_OF` | A 在 B 的某方位（北/南/东/西） | `{ a, b, dir }` |

> 方位定义：A 的质心坐标相对 B 的质心坐标满足方向关系（具体阈值在技术方案中定义）。

#### 4.3.6 唯一性条件 Uniqueness

| 子类型 | 含义 | 参数 |
| --- | --- | --- |
| `ONLY_ONE_CONTAINS` | 全局唯一拥有某属性的区域 | `{ attr }` |
| `ONLY_ONE_TOUCHES` | 全局唯一接触某地形的区域 | `{ terrain }` |

## 5. 玩家交互

### 5.1 基础操作

1. **选择组织**：点击组织标签（如「矿业公司」）进入该组织的划区模式。
2. **圈选区域**：MVP 阶段拖拽形成矩形；后续支持逐格点选构造任意形状。
3. **笔记标记**（类比数独笔记，三态）：
   - `MAYBE`（可能）
   - `EXCLUDE`（排除）
   - `CONFIRM`（确认）
4. **条件查看**：随时打开条件面板查看全部规则与「已满足/未满足」状态。

### 5.2 反馈系统

- **实时校验**：每次操作后实时计算「哪些条件已满足/冲突」，冲突条件高亮。
- **完成判定**：当所有格子分配完成且全部条件满足 → 通关。
- **错误不惩罚**：允许自由撤销/重做，鼓励推理而非记忆。

### 5.3 辅助功能

- 撤销 / 重做
- 清空当前组织区域
- 提示（Hint）：给出下一步可确定的逻辑结论（消耗提示次数，见 §8）

## 6. 难度成长体系

| 章节 | 主题 | 新增条件类型 | 目标 |
| --- | --- | --- | --- |
| 第一章 | 面积 | Area | 理解区域概念 |
| 第二章 | 资源 | Contain / Exclude | 理解包含与排除 |
| 第三章 | 邻接 | Adjacency | 理解接触关系 |
| 第四章 | 多组织 | 多 target + 覆盖要求 | 区域竞争 |
| 第五章 | 相对关系 | Relative | 比大小、方位 |
| 第六章 | 复杂地图 | 道路/河流/边界 + Border | 地形交互 |
| 第七章 | 高级推理 | 条件交叉 + Uniqueness | 多步逻辑链 |

**难度量化指标**（用于生成器分级）：

- 地图尺寸、区域数量、条件数量
- **逻辑链深度**：求解时需要的「强制推导步数」
- **分支因子**：每一步候选数量的均值

## 7. 关卡设计原则

每关必须满足三条硬性标准：

1. **唯一解**：满足全部条件的方案有且仅有一个。
2. **无猜测**：可从初始条件出发，通过一系列「强制单步推导」抵达唯一解，无需假设+回溯试错。
3. **可解释**：通关后可生成推理链解说，例如：
   > 因为 A 必须拥有金矿，金矿只在右上角 → A 只能在此 → 剩余面积约束下 B 只能选这里 …

> 「无猜测」的判定方法见技术方案中的「人类可解性（human-solvable）验证器」。

## 8. 商业化与运营（初版方向）

- **主线关卡**：手工/半自动生成 150~300 关，免费 + 付费章节解锁。
- **每日挑战**：每天 1 关，全球统一，可分享成绩。
- **周挑战**：更高难度，周末发布。
- **提示系统**：每日免费提示有限，可通过观看广告/内购补充。
- **去广告 / 主题皮肤**：内购点。

> 商业化为后续阶段，MVP 不实现付费/广告。

## 10. 内容生产系统

```
生成地图 → 生成区域答案 → 反推生成条件 → 验证唯一解 → 验证人类可解 → 难度分级 → 发布
```

- **手工关卡**：编辑器工具人工设计，自动跑唯一解校验。
- **自动生成**：CSP/SAT 思路程序化生成（详见技术方案 §自动生成）。
- **每日挑战**：离线批量预生成关卡池，按日程发布。

## 11. MVP 范围定义

**目标**：最快验证核心玩法是否好玩 + 关卡是否「唯一解、无猜测」。

### 11.1 MVP 包含

- 地图：5×5 ~ 7×7，固定尺寸。
- 区域形状：**仅矩形**。
- 组织数量：1~2 个。
- 条件类型：Area（面积）+ Contain/Exclude（包含/排除）+ 基础 Adjacency（接触地形）。
- 交互：选组织 → 拖拽矩形 → 三态笔记 → 实时校验 → 通关判定。
- 关卡：手工设计 10~20 关（覆盖第一、二、三章），全部通过唯一解校验。
- 平台：Web（桌面 + 移动端浏览器）。

### 11.2 MVP 不包含

- 任意形状/L 形区域
- 相对条件、唯一性条件、复杂地形（道路/河流）
- 自动关卡生成器（先做求解校验器即可）
- 账号系统、商业化、每日挑战服务端

## 12. 里程碑（产品视角）

| 阶段 | 内容 | 验收标准 |
| --- | --- | --- |
| M1 核心玩法原型 | 地图渲染 + 矩形圈选 + 校验 | 能手玩 1 关并正确判定通关 |
| M2 求解/校验器 | 唯一解 + 人类可解校验 | 给定关卡能判定是否唯一解 |
| M3 MVP 关卡包 | 10~20 关手工关卡 | 全部通过校验，可连续游玩 |
| M4 内测 | 难度曲线、引导、反馈打磨 | 内测留存与完成率达标 |
| M5 自动生成 + 每日挑战 | 生成器 + 服务端 | 可批量产出合格关卡 |

## 13. 风险与待决策

| 风险/问题 | 说明 | 建议 |
| --- | --- | --- |
| 自动生成「无猜测」关卡难度高 | 唯一解易，无猜测难 | MVP 先手工关卡，生成器作为 M5 攻坚 |
| 矩形限制是否够好玩 | 形状受限可能降低深度 | MVP 先验证，再决定是否开放任意形状 |
| 条件语义歧义（方位/接触） | 需统一形式化定义 | 已在本文 §4.3 与技术方案中固定 |
| 难度分级靠人工 | 主观且不可扩展 | 用求解器输出的逻辑链深度量化 |
